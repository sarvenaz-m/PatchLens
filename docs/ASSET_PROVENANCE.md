# Asset provenance and design

## GitHub banner

`docs/assets/github-banner.svg` is a scalable vector composition generated by `scripts/make_banner.py` from the committed fixture report. Model scores, sample counts and category labels come from that report. It is a repository banner, not a browser screenshot.

The banner uses the studio's navy, mint and coral palette. Its SVG contains no remote resources or executable code. Regenerate it after changing the reference results.

## Native interface assets

`src/patchlens/web/assets/mark.svg` is an original code-native vector mark included under the MIT licence. The interface uses system fonts and native SVG charts, with no CDN font, icon package, tracking pixel or network-loaded dependency.

| Role | Colour |
|---|---|
| Ink / navigation | `#142734` |
| Warm background | `#F5F6F2` |
| Primary teal | `#146D5D` |
| Mint tint | `#DFF3E8` |
| Error / vulnerable | `#A74332` |
| Focus / warm accent | `#CA8B54` |

Colour is paired with text labels and counts. Dark appearance uses a separate palette. The design supports reduced-motion preferences and visible keyboard focus; formal accessibility certification is not claimed.

## Data graphics

`reference-results.png` and `.svg` are generated by `scripts/make_figures.py` from the actual checked-in report. They display error counts and Wilson intervals, with class denominators visible. They are not generated imagery. Regenerate them after any change to the reference results.

## Actual interface captures

`workbench-overview.png`, `workbench-pairs.png`, `workbench-tools.png`, `workbench-diagnostics.png`, `workbench-compare.png`, `workbench-review.png`, `workbench-dark.png` and `workbench-mobile.png` were captured from the working version 1.0.0 interface in Chromium 138. They are screenshots, not generated mockups. `workbench-tour.webm` records actual navigation and controls through Playwright. Capture scripts are included.

`workbench-preview.gif` is a compact, looping conversion of that recording for the repository's front page. `scripts/make_preview.py` uses FFmpeg to resize and quantize the captured frames; it does not generate or modify the interface content. A static preview link is available beside the animation. The interactive demo uses the same self-contained `index.html` as the offline workbench.
